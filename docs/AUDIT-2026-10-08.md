# ClashEdge 源码审计与优化开发指令

> 审计日期：2026-10-08　基线版本：v1.0.9（`tauri.conf.json` / `Cargo.toml`）
> 方法：人工通读源码（Rust 后端约 10k 行、Vue 前端、C# 启动器、CI/打包脚本、Android 骨架）。
> **未编译、未运行测试、未做动态验证**。每条发现标注置信度：
> 【确】代码直接可证；【高】逻辑推演高度确定，建议按"复现步骤"实测；【中】依赖运行环境/威胁模型。

## 0. 总体评价

**做得好的（保持，不要回退）**

- `AppController` 事务串行锁 + 持久化 → 重生成 → 下发 → 回滚 → 通知的链路，思路清晰，回滚路径写得比同类客户端严谨。
- 系统代理 ownership journal（`proxy/journal.rs`）：完整状态比对、写后复读、外部接管时拒绝覆盖。
- SSRF 防护（`util/fetch/guards.rs`）：白名单式"全球可路由"判定、逐跳重定向校验、resolve pinning、SOCKS5 本地解析保留 SNI，有集成测试。
- 订阅只取 `proxies`，控制器地址限回环，控制器 secret 首次运行轮换为 128 位随机值，前端拿到的 secret 脱敏。
- 供应链：`assets.lock.json` 哈希锁定、Action 固定 commit SHA、manifest minisign 验签、启动器更新事务带 journal 与故障注入测试。
- 配置/订阅/日志均原子写入（随机后缀 + `sync_all` + rename）。

**主要风险画像**

1. **"能力已实现但没有闭环"**：更新器后端/启动器/CI 签名全有，但前端没有任何入口；多个设置开关不产生任何效果。
2. **进程与端口生命周期有盲区**：应用被强杀/崩溃后 mihomo 成为孤儿，下次启动因端口被占用而失败，且报错误导。
3. **运行时信任边界与构建期不一致**：构建期哈希锁定，运行期规则集/geodata 却从 `main` 分支浮动拉取且无完整性校验。
4. **SSRF 守卫与 TUN/fake-ip 冲突**（需实测）：开启 TUN 后订阅/更新/GeoData 拉取可能被自己的守卫拒绝。
5. **违反自家架构约束的旁路**：`set_locale` / `set_geodata_urls` 直接操作 `ConfigManager`，绕过事务锁与降级保护。

## 2. P0 开发指令

### A1　孤儿 mihomo：持久化子进程身份并在启动时回收

**现象**【确】
`start_locked` 直接 `spawn`，没有 Job Object，也没有落盘 PID。`cleanup_on_exit` 只在正常 `RunEvent::Exit` 触发。End Task / 崩溃 / 断电后 mihomo 继续运行并占住 7890 / 9090 / 9053。下次启动：新进程 bind 失败 → 但 `wait_ready` 会命中孤儿的控制器（secret 同为持久化值，鉴权通过）→ 随后 `detect_bind_conflict` 才从日志里抓到 `bind` → 报"请先关闭旧版 Clash.F.Win…"，**与真实原因无关**。

**指令**
1. 新增 `Data/core-session.json`（`atomic_write`），在 `cmd.spawn()` 成功后写入 `{ pid, image_path, started_at }`，在 `stop_locked` 确认退出后删除。
2. `start_locked` 在 spawn **之前**调用 `reclaim_orphan()`：读该文件 → 复用 `main.rs::owns_pid`（映像路径比对）→ 属于本应用的 mihomo 则终止并等待端口释放；不属于则只清文件，不动进程。
3. 终止方式改为：`OpenProcess(PROCESS_TERMINATE | PROCESS_QUERY_LIMITED_INFORMATION)` 取得句柄 → 校验映像路径 → `TerminateProcess(handle)`，**用同一个句柄**，消除"校验后 PID 被复用"的 TOCTOU（见 C2）。把 `owns_pid` 从 `main.rs` 挪到 `util/process.rs` 复用。
4. 不要给 mihomo 加 `KILL_ON_JOB_CLOSE`：崩溃时系统代理仍指向 7890，内核一起死会让用户立刻断网。孤儿的回收交给下一次启动（上一步）。
5. `detect_bind_conflict` 的错误文案改为"端口 N 被进程 X（PID）占用"，用 `GetExtendedTcpTable` 查占用者，不要写死"旧版 Clash.F.Win"。

**验收**
- 手动 `taskkill /F /IM ClashEdge.exe` 后重新启动：应用自动回收旧 mihomo 并正常运行，无 bind 错误。
- 另起一个无关进程占用 7890：启动失败，错误信息包含该进程名与 PID，且不会误杀它。
- 单测：`reclaim_orphan` 对"文件缺失 / PID 不存在 / 映像路径不匹配"三种情况均不杀进程。

### A2　自动更新：补齐 UI 闭环，并修复启动器"运行中应用更新"

**现象 1**【确】`updateApi`（`src/api/update.ts`）无任何视图引用；设置页、托盘均无"检查更新"入口；i18n 的 `update_available` / `update_staged` 文案无调用方。后端 `check_update` / `download_update` / 启动器事务 / CI 签名链全部是死代码路径。
**现象 2**【高】用户点窗口关闭只是隐藏到托盘；再次双击 `ClashEdge.exe` 时，启动器先 `ApplyPendingUpdate`（`:1065`），此时 `Directory.Move(rootApp, backup)`（`:651`）因内层 exe 正在运行而失败（需实测）。异常处理里 journal 状态为 `swapping`，不清理；下次启动 `RecoverInterruptedUpdate` 判定"App 有效"→ **删除 `Data/update-staging`**，已验签下载的更新包被静默丢弃。

**指令**
1. 前端：设置页新增"关于/更新"卡片：`检查更新 → 显示版本与 notes → 下载并校验 → 显示"已就绪，重启后安装" → [立即重启安装]`。托盘增加"检查更新"。进度与错误走现有 i18n key。
2. 新增 Rust 命令 `restart_and_apply_update`：先走 `cleanup_on_exit` 同一条路径（释放系统代理、停核心），然后 `spawn` 根启动器（`portable_root()/ClashEdge.exe`）并 `app.exit(0)`。
3. 启动器 `Main`：在 `ApplyPendingUpdate` 之前检测内层应用是否在运行（命名 Mutex，或枚举进程映像路径等于 `App\ClashEdge\ClashEdge.exe`）。**运行中则跳过应用更新**，只转发唤起参数，保留 staging。
4. 启动器失败语义：`Directory.Move(rootApp, backup)` 失败时（尚未改动 App）直接回到 `pending`，**保留 staging**；仅当 SHA 不符/解压校验失败时才删除 staging。
5. 自动检查：启动 N 秒后静默检查一次（沿用 `auto_update_subscription` 的"显式开关 + 单次、无常驻定时器"风格，新增 `auto_check_update` 设置项，默认开）。

**验收**
- 全流程：检查 → 下载 → 重启 → 版本号变化，`Data/` 不变。
- 有 pending 更新且应用在托盘运行时再次双击 `ClashEdge.exe`：只唤起窗口，staging 保留，更新在真正退出后的下次启动完成。
- 把 `--test-recovery` 增加"应用运行中"与"Move 失败"两个用例并进 CI。

### A3　SSRF 守卫与 TUN/fake-ip 的冲突

**现象**【高，需实测】`validate_url` 用系统解析器解析主机名，结果含 `198.18.0.0/15`（`guards.rs:198` 明确拒绝）即整体拒绝。开启 TUN + `dns-hijack: any:53` + `enhanced-mode: fake-ip`（均为默认）后，应用自身的 DNS 查询会被 mihomo 劫持并返回 `198.18.x.x`，于是 `get_direct_first` **第一步 `validate_url` 就失败**，直连与代理兜底都走不到。受影响：订阅导入/更新、GeoData 更新、更新清单、provider 展开、延迟测试 URL 校验。

**复现**：管理员运行 → 开 TUN → 设置页更新 GeoData 或更新订阅 → 期望看到 "resolves to a non-globally-routable address (198.18.x.x)"。

**指令**
1. 读取当前生效的 `dns.fake-ip-range`（默认 `198.18.0.1/16`）。当且仅当 **TUN 已启用且核心 Running** 且解析结果全部落在 fake-ip 段内时，进入"fake-ip 模式"：
   - 跳过直连尝试，直接走本地代理；
   - 本地代理 URL 使用 `socks5h://127.0.0.1:{port}`（由 mihomo 解析真实地址），不再 pin 到 fake IP；
   - 仍然保留 scheme / 主机名黑名单（`localhost`、`.local` 等）与字面 IP 白名单。
2. 在 `guards.rs` 里把"是否为 fake-ip"做成显式函数 `is_fake_ip(ip, range)`，**不要**把 `198.18/15` 从全局白名单里放开。
3. 保持"非 fake-ip 模式"下现有严格行为不变；新增测试：fake-ip 模式下通过、关闭 TUN 时同一地址仍被拒绝。
4. 可选的更稳妥方案：对守卫使用的解析改为通过 DoH（直连 `223.5.5.5`）取真实地址，完全绕开本机 DNS 劫持。

### A4　运行期规则集/geodata 的信任与完整性

**现象**【确】`default_rule_providers()`（`model.rs:606-640`）把 5 个规则集写成 `https://raw.githubusercontent.com/akaspyrean/external/main/rules/*.yaml`，`interval: 86400`，mihomo 自行拉取。构建期用 commit SHA + sha256 锁定，运行期却是浮动的 `main`，且没有任何内容校验。`direct` 规则排在 `GEOSITE,private` 之后，一旦该仓库被入侵/误提交，可把任意流量改为 DIRECT 或 REJECT。geodata 更新器（`updater.rs`）只校验大小与 HTML 前缀。另外 provider 未设置 `proxy:`，在中国大陆直连 raw.githubusercontent.com 经常失败，规则会静默停留在随包的旧版本。

**指令**
1. 在 `akaspyrean/external` 发布侧生成并签名 `rules-manifest.json`（版本、各文件 sha256、发布时间），复用现有 minisign 私钥与 `minisign-verify` 公钥。
2. 客户端新增"规则更新器"（复用 `update/mod.rs` 的验签与 `get_direct_first`）：下载 manifest + 签名 → 验签 → 下载各文件 → 校验 sha256 → 原子替换 `Data/rules/*`。
3. 运行时配置里的 rule-provider 改为 `type: file`（指向 `./rules/*.yaml`），**不再让 mihomo 自行 http 拉取**；刷新由上面的更新器负责，复用同一套 SSRF/代理兜底逻辑。
4. geodata：manifest 同样携带 sha256；`validate_geodata_content` 之外增加"用 mihomo `-t` 或加载校验"（至少校验 protobuf 可解析）。自定义 `geoip-url` / `geosite-url` 保留，但在设置页明确标注"自定义源不做签名校验"。
5. 在 manifest 中加入 `released_at` 与 `min_client_version`，客户端拒绝比本地已应用版本更旧的 manifest（防回滚/冻结）。同样的字段加到 `portable-manifest.json`（`make-update-manifest.py`）。

**验收**：篡改任一规则文件字节后更新失败并保留旧版；断网/GitHub 不通时回退镜像并提示。

## 3. P1 开发指令

### A5　启动器更新链与签名绑定
**现象**【中】启动器只比对 `pending.json` 里的 `sha256` 与 ZIP 实际哈希；写得动 `Data/update-staging` 的本地进程可同时放入恶意 ZIP 与匹配的 `pending.json`，下次启动即以用户权限替换 `App/`。便携目录本身用户可写，攻击者多数情况下可直接替换 exe，所以这条主要影响"便携目录位于只读/受保护位置而 Data 可写"的部署。
**指令**：`download_and_stage` 把已验签的 `portable-manifest.json` 与 `.minisig` 一并写入 staging；启动器内置公钥并验签后再取 sha256（.NET Framework 无 Ed25519，可内置 BouncyCastle 精简版或把验签放进一个只含验签的小 helper）。若短期不做，则在文档里明确威胁模型边界。

### B1　收口命令层旁路
**现象**【确】`commands/util.rs::set_locale` 与 `commands/geodata.rs::set_geodata_urls` 直接 `config_manager.lock().set_config(..)`：
- 违反 `docs/ARCHITECTURE.md` "不得在 command / tray 层直接操作 ConfigManager"；
- 绕过 `require_save_allowed_when_degraded`：配置损坏的降级模式下改个语言就会 `set_config` 并 **清除降级标志、覆盖损坏配置**；
- 与持锁中的事务做读-改-写会互相覆盖。
**指令**：在 `AppController` 增加 `set_locale()` / `set_geodata_urls()`（取 `tx` 锁，复用 `commit_config_locked` 或轻量的"仅持久化 + refresh_tray"路径）；命令层只做参数转发；两个命令补上降级守卫；`set_autostart` 的托盘刷新也走控制器。新增单测覆盖"降级模式下 `set_locale` 被拒绝"。

### B2　失败路径遗留临时文件
**现象**【确】`download_subscription_streaming` 在 `chunk().await?` / `write_all(..)?` 出错时不删 `temp_path`；`refresh_subscription` 的 `normalize_subscription_body(..).await?`（`:200`）与 `import_profile_from_url` 的 `:386`、`:396`、`:399` 同理。结果是 `profiles/*.yaml.tmp.<pid>-<n>` 持续堆积。
**指令**：引入 RAII 守卫 `TempFile { path, committed }`，`Drop` 时若未 `commit()` 则删除；三个函数统一使用。启动时清理 `profiles/` 下超过 1 小时的 `*.tmp.*`、`*.pending-delete`。

### B3　GeoData 更新器的三个缺陷
**【确】**
1. `download_file` 在响应体读取/写入失败时 `return Err`（`:261-279`），**不再尝试后续镜像**，与"多 URL 兜底"的设计相反。应 `continue`。
2. `geodata_sources` 对 `geox` 直接取默认值（`:384`），设置页的 `geox-url` 输入框无效。
3. 两个文件顺序更新，第二个失败时第一个已替换且不回滚；更新后没有通知核心重载。
**指令**：改为"先全部下载并校验到临时文件，再依次原子替换；任一失败整体回滚"；成功后调用 `reload_config`（或 mihomo 的 `/configs/geo`）；移除或实现 `geox-url`。

### B4　端口占用检测前置化 + 控制器端口动态化
**现象**【确】`detect_bind_conflict` 解析 `mihomo-stdout.log` 里的 `level=error ... bind`。用户把 `log-level` 设为 `silent`（允许）后失效，出现"运行中但代理端口已死"。固定的 `127.0.0.1:9090` 也很容易与其它 Clash 系软件冲突。
**指令**
1. spawn 前对 `mixed-port`、`dns.listen`、控制器端口做 `TcpListener::bind` 预检（失败则报占用者，见 A1-5）。
2. 控制器端口改为每次启动选一个空闲端口（写入内存态的 `runtime` 配置，不持久化到用户可编辑项），`ControllerClient` 动态读取。
3. 启动后以 `GET /configs` 核对 `mixed-port`，并对 `127.0.0.1:mixed-port` 做握手探测（与 `verify_runtime_applied` 一致）。
4. 中期：评估 `external-controller-pipe`（Windows 命名管道）彻底去掉控制器 TCP 暴露面。

### B5　合并"首次启动"与"自动重启"两条 spawn 路径
**现象**【确】`supervisor.rs:260-326` 手写了一遍：读 profile、写 runtime、建日志、spawn。与 `lifecycle.rs` 已不一致：自动重启不做日志轮转、不做 `detect_bind_conflict`、不经过 `lifecycle` 锁。两处 `File::create(mihomo-*.log)` **截断**日志，崩溃循环里第一次崩溃的 stderr 立刻被覆盖。
**指令**：抽出 `CoreManager::spawn_mihomo(&self) -> Result<Child>`（含写配置、日志轮转、`CREATE_NO_WINDOW`），两处共用；日志改为追加 + 启动时按大小轮转为 `.1/.2/.3`；watcher 的重启通过 `restart_locked` 并在重启前检查 `generation`。

### B6　控制器与日志流客户端必须 `no_proxy()`
**现象**【高】`ControllerClient::new` 与 `spawn_log_stream` 的 `reqwest::Client` 未禁用代理。环境变量 `HTTP(S)_PROXY`、企业 PAC、或其它软件设置的系统代理下，回环请求可能被代理而失败（日志流 `Client::new()` 尤甚）。
**指令**：所有指向 `external-controller` 的 client 统一 `.no_proxy()`；把日志流改用 `ControllerClient` 的同一个 client 与 `api_url`；对 SSE 行缓冲加上限（如 1 MiB）。

### B7　订阅兼容性与校验
**【确】**
- 拉取 UA 固定为 `ClashEdge/x.y.z`（`client.rs:40`）；不少服务端按 UA 返回不同格式。`normalizer` 明确不支持 Base64 / URI 列表。
- 不解析 `Subscription-Userinfo`（已用/总流量/到期）。
- `validate_subscription_content` 不检查节点重名、与内置组/保留字（`DIRECT`、`REJECT`、`GLOBAL`、`人工优选`…）同名；`create_profile` / `update_profile_content` 不走 normalizer 的 `dedupe_by_name`，冲突会在 mihomo 启动时才暴露为晦涩错误并触发回滚。
**指令**
1. 订阅请求 UA 改为 `clash.meta` / `mihomo` 兼容值（`ClashEdge/x (mihomo)`），支持用户为单个订阅覆盖 UA。
2. 新增 URI 列表/Base64 解码器（ss/ssr/vmess/vless/trojan/hysteria2/tuic）→ 统一产出 `proxies`；失败时给出"服务端返回了不受支持的格式"的明确提示。
3. 解析并展示 `Subscription-Userinfo`（存入 profile 元数据，见 C8）。
4. `validate_subscription_content` 增加：节点名唯一、非保留字、非纯数字（YAML 会解析成数字导致名称丢失）；错误信息带节点序号。

### B8　减少不必要的热重载
**现象**【确】`commit_config_locked` 对所有字段变更都 `reload_config`（PUT /configs + 健康检查），改语言/混入开关也会触发。
**指令**：`write_runtime_config` 返回内容哈希；与上一次已应用的哈希相同则跳过 reload，只持久化 + 刷新托盘。顺带为 `local_proxy_url`、`port_alive` 等只需端口的路径增加 `ConfigManager::mixed_port()`，避免每次 `get_config()` 深拷贝整份配置（含 `extra`、`rules`、`rule_providers`）。

### B9　清理死开关/死配置（违反"UI = 真实状态"）
**【确】** 下列项目在设置页或模型中存在，但后端没有任何消费方：

| `mixin-enabled`（托盘 + 设置页开关） | `app_controller.rs:173`、`tray/builder.rs:81` | 实现真实的配置覆写（用户 YAML 深度合并到 runtime）或删除开关与事件 |

规则：每个暴露给用户的开关必须有"变更 → 运行时可观察效果"的测试。

### B10　CI / 发布流水线
**【确】**
1. `release.yml:11-14`：整个 `build` job 持有 `contents: write` + `id-token: write` + `attestations: write`，而 `npm ci` 与 cargo 构建脚本（第三方代码）都在同一 job 内运行。
2. "Validate release artifacts" 只检查文件存在与哈希一致，**不验证签名**。若 `CLASHEDGE_UPDATE_PUBKEY` 与私钥不配对，发布成功但所有客户端永远验签失败。
3. 启动器仅在 release 的 `build-portable.ps1` 里编译，CI 不编译、不跑 `--test-recovery`。
4. `rust-toolchain.toml` 为浮动 `stable`，`-D warnings` 会被新版 clippy 随机打断；`quality.ps1:69` 每次 `cargo install cargo-audit`；`Cargo.lock` 中 `reqwest`/`winreg` 各有两个版本。
**指令**
1. 拆成 `build`（`contents: read`，无 secrets）→ `sign-and-publish`（仅 `download-artifact` + 签名 + 发布，持有写权限与密钥）。
2. 发布前增加验签步骤：用公钥对刚生成的 `.minisig` 验证 manifest（可写一个 20 行的 Rust/Python 校验脚本或 `minisign -V`）。
3. 把"编译启动器 + `--test-recovery`"放进 `quality.ps1`（CI 同跑）。
4. 固定 Rust 版本（例如 `channel = "1.9x.y"`）；`cargo-audit` 改用 `taiki-e/install-action` 或缓存；评估 `cargo deny` 检查重复依赖与许可。
5. manifest 增加 `released_at`；发布产物附 SBOM（`cargo cyclonedx` / `cargo auditable`）。

### B11　Authenticode 代码签名
**现象**【确】`tauri.conf.json` 中 `certificateThumbprint: null`；C# 启动器与内层 exe 均无签名。该软件会改系统代理、拉起子进程、写注册表自启，未签名时 SmartScreen / 杀软误报概率高（`paths.rs` 的提示文案已经体现了"杀软拦截内核"的真实用户问题）。
**指令**：接入 Azure Trusted Signing 或 SignPath（开源项目免费方案），对 `ClashEdge.exe`、`App/ClashEdge/ClashEdge.exe` 签名；mihomo/wintun 在 `prepare.ps1` 里校验其自带的 Authenticode（wintun.dll 带 WireGuard 签名，可用 `Get-AuthenticodeSignature` 校验发布者）。

## 4. P2 开发指令

### C1　启动器细节（`ClashEdge.Launcher.cs`）
- `ExtractJsonField`（`:290`）是手写字符串切片，遇到转义反斜杠/引号会错位（`zip_path` 实际带 `\\`，目前靠 Win32 路径归一化"碰巧能用"）。改用 `DataContractJsonSerializer`（.NET Framework 自带）。
- `CopyMissing` / `MoveContents` 用 `file.Replace(source, destination)`（`:95-98,115`）：路径中出现多次 `source` 子串时会被全部替换。改用 `Substring(source.Length)`。
- `CreateJunction` 通过 `cmd /c mklink /J` 拼命令（`:157`），路径含 `%` 会被展开。改用 `CreateDirectory + DeviceIoControl(FSCTL_SET_REPARSE_POINT)`，或 P/Invoke `CreateSymbolicLink` 的 junction 变体。
- `Quote`（`:165`）对尾部反斜杠与内嵌引号处理不符合 `CommandLineToArgvW` 规则。
- `--user-data-dir=` 被当作应用参数传给 Tauri exe，WebView2 并不读取该参数；目前靠重定向 `LOCALAPPDATA` 起作用。要么删除该参数，要么改用 `WEBVIEW2_USER_DATA_FOLDER` 环境变量。
- 升级时 `CopyMissing(DefaultData → Data)` 只补缺失文件：新版本随包带来的更新规则/geodata 永远不会覆盖老用户的 `Data/`。给 `DefaultData` 增加版本戳，用户未修改（对比旧版哈希）时才覆盖。

### C2　进程终止
`stop_locked` 的兜底与 `cleanup_on_exit` 都用 `Command::new("taskkill")`：未设 `CREATE_NO_WINDOW`（退出时闪一下控制台）、PID 校验与终止之间有复用窗口。统一改为 A1-3 的"持句柄终止"，删除对 `taskkill` 的依赖。

### C3　前端体积与常驻内存
- `main.ts:4-6,45-48` 全量引入 Element Plus 与全部图标并全局注册。改为 `unplugin-vue-components` + `unplugin-auto-import` 按需引入，图标只注册用到的。
- 托盘常驻应用的主要内存是 WebView2。`CloseRequested` 目前是 `hide()`；改为"隐藏 N 分钟后销毁 webview，托盘唤起时重建"，并让 `core-status-changed` 等事件在窗口不存在时直接丢弃。
- `LogsView` 的 SSE 流在窗口隐藏时仍然运行；与 `ConnectionsView` 一样监听 `visibilitychange` 暂停。
- 阻塞 IO 在 async 命令里同步执行（`list_profiles` 逐个 `read_to_string` 最大 10 MB 的 profile 只为取第一行 URL；`get_profile_content` 等）。改为 `spawn_blocking`，并把订阅元数据（URL、更新时间、节点数、流量）落到 `profiles/index.json`，`list_profiles` 不再读全文。

### C4　Tauri 权限收敛
`capabilities/default.json` 含 `dialog:default`，而前端从未导入 `@tauri-apps/plugin-dialog`（`package.json:15` 为无用依赖；文件选择在 Rust 侧 `pick_import_file`）。删除该权限与 npm 依赖；`core:window:allow-close` 与 `allow-show` 确认确实被前端使用后再保留。

### C5　依赖与工具链
- `serde_yaml 0.9.34+deprecated` 已归档，而它解析的是不可信订阅。规划迁移（`serde_norway` / `yaml-rust2` 方案），迁移前把 YAML 解析封装在一个模块，避免散落。
- 清理 `Cargo.lock` 中重复的 `reqwest 0.12/0.13`、`winreg 0.11/0.55`。
- `Cargo.toml` 中 `tokio = { features = ["full"] }` 收窄到实际使用的特性，缩小二进制。

### C6　日志
`util/logging.rs`：`clash_edge` 目标在 release 也是 `Debug`，并同时输出到 Stdout / Webview / 文件。确认 `tauri-plugin-log` 的默认单文件大小与保留策略（默认值偏小、只保留少量历史），显式设置 `max_file_size` 与 `rotation_strategy`；release 默认 `Info`，在设置页提供"诊断模式"开关。同时提供"导出诊断包"（脱敏后的 `config`、最近日志、mihomo 日志、版本信息）。

### C7　默认运行时配置
- `tun` 缺少 `strict-route`、`route-exclude-address`、`mtu`、`device` 等常用项，Windows 多网卡下存在 DNS 泄漏面；暴露 `strict-route`（默认 true 或在高级里提供）。
- 订阅的 `sniffer` 被刻意屏蔽，但应用自身从不启用嗅探：TUN 下纯 IP 连接无法按域名规则分流。评估默认启用 `sniffer`（`TLS/HTTP/QUIC`，`force-dns-mapping`、`parse-pure-ip`）。
- `TunConfig.interface_name: Option<String>` 序列化为 `interface-name: null`，加 `skip_serializing_if = "Option::is_none"`。
- Windows ARM64：`assets.lock.json` 仅 `windows-amd64-compatible` 与 amd64 `wintun.dll`，补 arm64 变体。
- 规则 provider 设置 `proxy:`（见 A4）。

### C8　订阅元数据与凭据存放
订阅 URL（含 token）以明文写入 `profiles/*.yaml` 头注释。至少把元数据（URL/UA/更新时间/流量）拆到 `profiles/index.json`，并对 URL 使用 DPAPI（`CryptProtectData`，当前用户范围）加密存放；便携迁移到另一台机器时提示"需重新输入订阅地址"。

### C9　控制器暴露面（中期）
见 B4-4：命名管道 + 每次启动随机 secret（不落盘），移除 `config.yaml` 里的长期 secret。

### C10　小清理
- `core/config.rs:317-335`：变量 `has_auto_group` 语义相反（实际是"需要移除自动组"），改名 `drop_auto_group`。
- `ARCHITECTURE.md` 中 "`commands/` 不放业务状态" 与 B1 的旁路矛盾，修复后在文档加入"禁止 `config_manager.lock().set_config` 出现在 `commands/` 与 `tray/`"，并加一条 `cargo test` 级别的 grep 守卫。
